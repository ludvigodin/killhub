## Platform shape

| ID | Decision | Rationale |
|----|----------|-----------|
| D27 | **Two planes:** (1) durable **control plane** (Next.js + agent/harness workers) · (2) **one disposable Microsandbox microVM per job**. There is no separate Explore VM vs Test VM — explore and test share that same sandbox. | Operator choice: same disposable compute for discovery and runtime; avoids dual-VM cost and drift |
| D28 | **Plane 1 owns Jobs API + SSE** (Next.js). It starts the plan loop and launches/destroys the disposable sandbox via the harness. `explore/` is a same-host worker/library under Plane 1, not a disposable VM and not a separate plane. | Durable job state cannot live in an ephemeral sandbox |
| D1 | ~~Three planes: Next.js · Explore Sandbox · Test VM~~ → **superseded by D27** | — |
| D2 | ~~Plane 1 does not run the agent or provision VMs~~ → **superseded by D28** (Plane 1 owns orchestration; browser still must not hold secrets) | — |
| D3 | ~~Plane 2 owns plan loop and harness~~ → **superseded by D28** (plan loop + harness run on the control plane) | — |
| D4 | Disposable Microsandbox per job on Vultr VX1 — **retained**; clarified by D27 that this single sandbox is both explore and test | Ephemeral KVM isolation; destroy on `completed` / cancel / fail / absolute expiry (D37, D41) |
| D5 | ~~Primary v1 intents: **`git_mcp` \| `webapp`**; unknown intents blocked/flagged~~ → **superseded by D34** | — |
| D34 | Environment Agent **decides** how to demonstrate the repo. Prefer **`git_mcp`** or **`webapp`** when those fit; otherwise invent a minimal **`demo`** (e.g. serve a lone `.txt` / puzzle as a tiny HTTP page or scripted verify) and put that plan in `environment_profile.json`. Hard-fail only when no verifiable demo can be launched within caps — not merely because the repo is not MCP/webapp. Readiness for `demo` = the profile’s declared probe (typically HTTP 200 or a command exit 0 with logged evidence); still **verifiable execution**, not a chat description. **Outcome honesty** required by D54 — a generated demo must not be labeled as original-application success. | Operator wants agent judgment: “bring it up somehow” including edge repos |
| D6 | Canonical artifact: **`environment_profile.json`** (runtime). Bootstrap create uses a separate Killhub-owned bootstrap profile (D36). Versioned executable schema: **D51**. Profile **revisions** and current pointer: **D64**. | Clear handoff from discovery to sandbox provisioning |
| D51 | **Versioned executable profile schema (`schema_version`).** Runtime (and bootstrap) profiles are a complete contract: `services[]` (name, image/package, ports, health, env, depends_on), `commands[]` / install/run entries with **`cwd`**, argv/shell, env, timeout; **process supervision** (`supervise`: oneshot \| restart, stop signal, readiness delay); **probes** with explicit types. For MCP: required **`mcp.transport`**: `stdio` \| `streamable_http` (and optional URL for HTTP). **`stdio` readiness** is not an HTTP ping — Plane 2 runs an **in-guest MCP verify helper** that launches the server subprocess, speaks JSON-RPC over stdin/stdout (`initialize` → `notifications/initialized` → `tools/list`), and returns structured evidence. Schema lives in-repo (`schemas/environment_profile.v1.json`); breaking changes bump `schema_version`. | PROFILE was underspecified; MCP stdio ≠ HTTP healthcheck |
| D36 | **Bootstrap sandbox before discovery.** Plane 1 creates the job’s microVM from a Killhub-owned, schema-valid **bootstrap profile** (`intent: bootstrap`, `MSB_DEFAULT_IMAGE` / discover image, clone-only). Inspection runs inside that VM. The agent then writes the **runtime** `environment_profile.json`. If discovery selects a different `oci_image`, harness **replaces** the same job’s sandbox (stop+remove bootstrap → create with new image → re-clone at the **resolved commit** — D62) — **never two concurrent microVMs for one job** (D27). Same-image discovery continues in place. Invalid **runtime** profiles must not start provision/install; bootstrap create is exempt because the bootstrap profile is trusted and pre-validated. Replacement inherits the original job `expires_at` and records a new **sandbox generation** (D64). Private Killhub-owned bootstrap/runtime base images are stored in **Vultr Container Registry** and pinned per **D74**. | Breaks inspect↔create circular dependency without a second plane or dual-VM explore/test split |
| D74 | **Vultr Container Registry is the supported private OCI store** for Killhub-owned bootstrap and runtime base images (`MSB_DEFAULT_IMAGE` / profile `oci_image`). Image form: `<region>.vultrcr.com/<registry>/<repo>[:tag\|@sha256:<digest>]`. **Prod pins by digest.** Robot accounts (or minted docker credentials) authenticate the **Plane 1 / VX1 host** (docker credential store → `msb` create pull) only — **never** inject `VULTR_CR_ROBOT_*` into guest sandbox env (D19, D44). Harness fail-closes when a `*.vultrcr.com` ref is used without host robot creds unless `VULTR_CR_REQUIRE_CREDS=false` (deliberately public registry). Operator login: [`explore/scripts/vultr_cr_login.sh`](explore/scripts/vultr_cr_login.sh); procedure in [SETUP.md](SETUP.md) §6. Does not provision a registry subscription automatically. | Trusted bootstrap images without public-registry dependency; keeps pull secrets off the guest |
| D64 | **Profile revisions + sandbox generations.** Persist every accepted profile as an append-only **revision** (`job_id`, `revision`, `phase`, `profile`, …) with `Job.current_profile_revision`. Persist every create/replace as a **sandbox generation** (`job_id`, `generation`, `environment_id`, `image`, `expires_at`, `state`, per-generation `destroyed_at`) with `Job.current_sandbox_generation`. Job-level `sandbox_id` / `destroyed_at` always describe the **current** generation (or final confirmed absence). When a bootstrap VM is removed during replace, set **that generation’s** `destroyed_at` and `state=replaced` — do **not** set job-level `destroyed_at` while a replacement is alive. Replacement must reuse the original job `expires_at` (never extend). Receipt history cites revision + generation ids. | One-row-per-job cannot represent bootstrap→runtime repairs or replacement history the receipt promises |
| D62 | **Resolved commit is mandatory; original_application launches the built checkout.** After the first successful clone, every job persists `resolved_commit` (full SHA). Runtime `source.commit` is **required** (not optional). Every re-clone (including after image replace) must check out that exact SHA. Claiming `verification.kind=original_application` requires launching the **built tree from that checkout** (local `node`/`python`/binaries under the workdir or packages already installed into that tree). Do **not** satisfy original-application readiness by `npx -y <unpinned-package>` or other commands that resolve/install a package absent from the local checkout/lockfile. Fixtures pin SHAs in [explore/fixtures/m7.json](explore/fixtures/m7.json) (D53). | Readiness must prove the inspected source; unversioned registry launches can retrieve different code |
| D22 | Plane 2 runtime = **[Microsandbox on Vultr Cloud Compute](https://docs.vultr.com/how-to-set-up-agent-sandboxing-on-vultr-cloud-compute)** (`msb` / SDK over KVM+libkrun) | Official Vultr agent-sandboxing path |
| D24 | **Public / demo control plane** runs on **Vultr Cloud Compute** at **[https://killhub.pro](https://killhub.pro)**; local `docker-compose` remains for development only | Vultr is the orchestration fabric, not only sandboxes; single marketed demo hostname |
| D80 | **Lost-sandbox self-heal + in-flight orphan guard (2026-11-27).** If a job's microVM vanishes mid-pipeline (`msb status` → not found, or "shutdown is already in progress"), the worker records a `lifecycle` `sandbox lost` event, marks that generation `failed`, force-removes any remnant, clears `sandbox_id` and re-runs the pipeline on a fresh generation, at most `MAX_SANDBOX_HEALS` times (default 1, 0 = off). The install repair loop aborts with `sandbox_lost` instead of retrying against a dead VM. The reaper no longer destroys a "live sandbox with no ledger generation" whose labeled job is still in flight (create → generation write is not atomic); absolute `expires_at` reaping is unchanged. Still one live VM per job (D27); never extends `expires_at` (D41); readiness still only from gates (D47). | Live demo jobs failed with `canary_plant_failed` (reaper killed a just-created VM as orphan) and `msb snapshot create … sandbox not found` (VMs removed from the host mid-install); repairs 2–3 then ran against a missing VM. |

Still never inject Killhub secrets into the sandbox. | Match “everything Vultr/Microsandbox can run”; honesty over false green |
| D10 | Repair/readiness retries capped by **`MAX_REPAIR_ATTEMPTS`** | Bound cost and infinite loops |

Terminal outcome for advisory-only findings is governed by the gate table (**D66**) — by default they do **not** block `completed`. | Visibility without erasing probe proof |
| D33 | **Vulnerability posture in v1:** always run **SCA / lockfile / known-advisory scans** + AI `vuln_review`. **Do not** weaponize CVEs or run generic app/web pentest / exploit suites against the submitted project. **Containment probes (D26)** prove sandbox isolation only. **MCP protocol/tool assessment** is allowed only when the agent plans it (**D35**) — that path is not a blanket pentest license. | Scan + report by default; optional MCP assessment is opt-in via profile |
| D35 | When the Environment Agent encodes an **MCP security assessment** in `environment_profile.json` (typically under `mcp.security_assessment` for `git_mcp`), Plane 2 **may** run **MCP Inspector and/or MCP SDK** probes after readiness (tool/schema surface, safe fixture-backed calls). Assessment is **agent-planned and optional**; it must **not** invalidate readiness or gate `completed` (D30 / D37). Findings stream into the job report alongside SCA. If the profile omits assessment, skip Inspector entirely. Assessment/browser tooling must already be present before the verify offline phase (D63). | Operators want MCP security testing when the repo warrants it, without making every job an offensive campaign |
| D30 | **`git_mcp` readiness** = real **MCP handshake** that can list tools (not merely process-alive or HTTP ping) | Proves the MCP server speaks the protocol |
| D31 | **Screenshots are optional.** Capture when useful (e.g. HTTP webapp verify); skip for CLI-only MCP or early fail. Missing screenshots must **not** invalidate readiness or block `completed`. | Not every job has a meaningful still |
| D37 | **Separate readiness from job completion.** `readiness` is probe evidence (`passed` / probe / detail) set when the profile probe succeeds. Terminal success status is **`completed`**, reached only after bounded report generation (SCA + `vuln_review`, optional MCP assessment), artifact capture, and sandbox cleanup. Do **not** destroy the sandbox merely because readiness passed. Destroy on `completed` \| `failed` \| `cancelled` \| absolute expiry (D41). Findings / optional assessment failures do not clear `readiness.passed`. Gate outcomes (D66) may fail the **job** without clearing readiness evidence. | Prevents premature destroy when “ready” meant both probe-ok and job-finished |

| ID | Decision | Rationale |
|----|----------|-----------|
| D69 | **Public job feed list.** Plane 1 exposes **`GET /api/jobs`** (proxied to **`GET /internal/jobs`**) returning a capped, newest-first summary list for the demo home feed (`job_id`, `github_url`, `status`, `progress`, `current_step`, timestamps, optional latest `screenshot_id`). Full dossier remains on `GET /api/jobs/{id}`. | D77 | **Feed list pagination is server-side.** `GET /api/jobs` / `GET /internal/jobs` accept **`limit`** (default 48, max 200) and **`offset`** (default 0) and return `{ jobs, total, limit, offset }` with ledger `COUNT(*)` for `total` and SQL `LIMIT`/`OFFSET` for the page (newest-first, same tie-break as D69). The UI pages via these params — it must not fetch a giant window and slice client-side. | Demo feed grows beyond one viewport; keep Plane 1 thin and queries bounded |
| D79 | **Home feed is repo-grouped by canonical `github_url`.** `GET /api/repos` / `GET /internal/repos` return one row per distinct URL (`github_url`, `run_count`, `latest` JobSummary), paginated newest-activity-first. Cards link to `/repos/{host}/{…path}` which lists runs via `GET /api/jobs?github_url=` (exact match after D78 validation). Jobs remain independent ledger rows — no batch/parent id. Flat `GET /api/jobs` stays for history + tooling. | Re-running the same repo cluttered the flat feed; operators need history without inventing a new identity model |
| D12 | Jobs are **server-owned**; disconnect ≠ cancel | Long pipelines survive tab close; cancel is explicit `DELETE` or timeout |
| D13 | Dual channel: **poll `GET /jobs/{id}` + SSE `/events`** must stay consistent | Robust UI + live updates |
| D14 | ~~SSE types: `status`, `progress`, `log`, `screenshot`, `error`~~ → **extended by D49** (those five remain; evidence types added) | — |
| D49 | **Structured evidence stream + job receipt.** SSE types: `status` · `progress` · `log` · `screenshot` · `error` · **`span`** · **`finding`** · **`containment`** · **`lifecycle`** · **`gap`** (D67). Keep-alives (D50) may use comment frames or empty `progress` heartbeats. Every job produces a durable **receipt** on Plane 1 that outlives the sandbox: profile revision(s), readiness, findings, containment/network probe results, sandbox generation lifecycle (`created` / `replaced` / `destroyed`), outcome gates, and `vuln_review` citations. Destroy evidence is required on every terminal path. Receipt is written **before** terminal status, including on cancel (D61). | Operators need an audit dossier, not only a progress bar |
| D50 | **SSE keep-alives** during long install/verify/scan steps (at least every ~15s while the stream is open) so clients do not appear stalled | Long Microsandbox steps otherwise look dead |
| D15 | ~~Public **HTTPS github.com** URLs only in v1~~ → **superseded by D78** (allowlisted public git hosts) | Reduce auth and SSRF surface |
| D78 | **Public HTTPS git URLs on an allowlist** — `github.com`, `gitlab.com`, `bitbucket.org`, `codeberg.org` — with optional trailing `.git`. Reject non-HTTPS, SSH, credentials/query/fragment, non-allowlisted hosts, and UI path junk (`/tree/`, `/-/`, …). Wire/DB field stays **`github_url`** for API stability; user-facing copy says “public git URL.” Pre-flight: GitHub keeps `api.github.com` metadata; other hosts use cheap HTTPS reachability on the same allowlisted host (no off-host redirects). Archives, uploads, and self-hosted git are out of scope. Implementation: `explore/git_url.py`, `frontend/lib/github.ts`. | Operators paste GitLab/Bitbucket/Codeberg without widening SSRF to arbitrary HTTPS |
| D40 | **Public demo admission controls.** Per-job CPU/memory/timeout caps do not bound aggregate demand. Plane 1 enforces: **global concurrency** (`MAX_CONCURRENT_JOBS`), a **bounded queue** (`MAX_QUEUED_JOBS`), **request throttling** (per-IP / global rate limits on `POST /api/jobs`), **per-job and rolling inference budgets** (token/wall-clock), and **disk/log caps** (profile/screenshot/event retention sizes). Reject with `429` (rate / inference budget) or `503` (concurrency / queue full) and a clear error body — never silently drop. | Anonymous access needs hard admission, not only per-sandbox limits |
| D45 | **Plane-1 pre-flight before bootstrap sandbox create.** After URL validation + admission (D78, D40), run cheap checks on the control plane (GitHub metadata and/or allowlisted-host reachability): rate/abuse already applied; optional known-malicious dependency / advisory pre-screen when cheap; reject or short-circuit with findings **without** creating a Microsandbox when pre-flight hard-fails. Soft signals may continue into the job with findings attached. | Avoid burning VX1 for obviously hostile or invalid intakes |
| D52 | **Python sidecar owns job state.** Close the Next.js↔`explore/` non-decision: **`explore/` is a same-host localhost sidecar** that owns the durable ledger and workers. Next.js is a thin public edge (UI + `/api` proxy) and does **not** hold the job dictionary. Internal Worker API (loopback + `INTERNAL_API_TOKEN`): `POST /internal/jobs`, `GET /internal/jobs` (recent summaries — D69), `GET /internal/jobs/{id}` (snapshot), `GET /internal/jobs/{id}/events` (SSE), `DELETE /internal/jobs/{id}` (cancel), plus screenshot routes as needed. Define and freeze this interface **before** N1/E1. | Next.js and Python cannot share an in-process dict; one state owner avoids split-brain |
| D81 | **Operator Killhub MCP (stdio + public HTTP JSON-RPC).** Agents/operators drive Killhub via MCP that speaks the **public** Jobs API — not the browser and not harness. Shared tools in `explore/operator_mcp_tools.py`; stdio entry `explore/operator_mcp.py`; HTTP `POST /internal/mcp` proxied as public **`/mcp`**. Tools: `create_job`, `create_jobs` (max 5), `create_and_wait`, `get_job` (verbose), `get_job_status`, `get_receipt`, `list_jobs`, `list_repos`, `list_fixtures`, `run_fixture` (public M7: `webapp_success` \| `git_mcp_filesystem` \| `setup_failed`), `cancel_job`, `wait_job` (soft timeout → `done=false` status; default 60s), `tail_events` (via `GET …/events/recent`), `list_screenshots`. Resources: template `killhub://jobs/{job_id}/screenshots/{shot_id}` → public URL text (not base64). Calls `KILLHUB_BASE_URL` public `/api/*` (default `https://killhub.pro`) so admission (D40) applies — never a backdoor to `/internal/jobs` with the server token for creates. Optional `KILLHUB_API_TOKEN` Bearer for future auth; demo stays anonymous. **Distinct from** `killhub-harness` (D23/D38) and Vultr/hackbus (D59). | Operators want Cursor/Claude to paste URLs, wait for slim receipts, and use fixtures without leaving the agent |
| D55 | **SSE cursor contract.** Snapshot includes `event_cursor` (last durable `event_id`). Clients hydrate snapshot then subscribe with `Last-Event-ID` / `?after=`. Retain events for `EVENT_RETENTION` (at least job active lifetime + configurable post-terminal window) subject to byte-budget pruning rules in **D67**. Unknown/expired cursor → `410` or SSE `error` with `code=cursor_expired`; client must re-snapshot and resubscribe — never silently skip a gap. | Prevents missed events between hydrate and subscribe |
| D67 | **Event retention is contiguous; no silent holes.** When `MAX_JOB_LOG_BYTES` is exceeded, prune a **prefix** of the oldest durable events for that job (contiguous from the start of the retained sequence). Never delete middle events while keeping older and newer neighbors. After a prune, insert exactly one durable `gap` event (or tombstone with `type=gap`) documenting `{ pruned_before_event_id, pruned_after_event_id?, bytes_freed }` so replay after that point remains contiguous. A fresh snapshot’s `event_cursor` is the last **retained** event; SSE replay from a valid cursor is gap-free forward. Cursors that fall inside a pruned range are expired (D55). Active-job retention promise means the **current retained window** is complete — not that every historical byte since create is forever available once budgets bite. | Dropping selected old payloads left holes after an otherwise valid cursor |
| D61 | **Cancel ordering: request → freeze → finalizer → terminal.** On `DELETE`: (1) set `cancel_requested_at` immediately and freeze **ordinary** workers (plan loop, install, repair, assessment, non-finalizer status/progress/profile mutations); (2) enter bounded **finalizer** work while status is non-terminal (`finalizing` with cancel intent, or keep prior phase visibly frozen); (3) finalizer **may** write the allowlisted fields: `cleanup.*`, destroy/lifecycle evidence, `receipt`, cancel `log`/`span`, progress/current_step for cleanup only, and `status` transitions into `finalizing` then terminal `cancelled`; (4) persist receipt **before** setting terminal `cancelled`; (5) SSE stays open until terminal status. Repeated `DELETE` on already-`cancelled` is idempotent with the same terminal snapshot. Cancel during bootstrap/create aborts in-flight `msb create` (best effort) and destroys any partial sandbox via the same finalizer path. Supersedes the earlier D56 wording that set `cancelled` before receipt. | Receipt is mandatory on every path; early `cancelled` made finalizer writes and SSE closure ambiguous |
| D56 | ~~Cancel commits `cancelled` then allows only cleanup writes~~ → **superseded by D61** (ordering + explicit finalizer allowlist; idempotency retained) | — |

| D20 | Agent tools may only target harness / sandbox APIs — **never** execute untrusted repo install/run on the control-plane host | Discovery reads via clone/`msb` copy/exec inside the sandbox |
| D38 | **OpenCode lockdown (enforceable).** Plane 1 runs the Environment Agent under a **trusted system/managed OpenCode config** (host-owned; outranks project/user config). | D58 | **Containment evidence matrix.** Before claiming isolation, the harness must record structured evidence for: (1) **timeout_enforcement** — adversarial loop absorbed by timeout/kill; (2) **host_access_denied** — guest cannot reach host/control-plane/management destinations (aligns D39); (3) **sibling_access_denied** — cannot reach another job’s sandbox; (4) **host_liveness** — host/control-plane remains healthy during the probe (no crash/OOM attributed to the guest). Stream as `containment` SSE / receipt fields. Missing dimensions ⇒ containment claim incomplete, not “proven.” Not CVE exploitation of the submitted app (D33). | D65 | **Containment probes need positive controls and policy-vs-infra distinction.** Failed fetches alone are not isolation proof. For each deny claim: (1) use **known-live targets** (control-plane URL / management endpoint that Plane 1 confirmed reachable from the host during the same job window); (2) run a **positive control** from a permitted vantage (e.g. host-side fetch succeeds) before treating guest failure as deny; (3) classify outcomes as `policy_denied` \| `infra_error` \| `tooling_missing` \| `inconclusive` — only `policy_denied` (with live target + positive control) counts toward `host_access_denied` / sibling deny; (4) also probe control-plane denial during the **install** phase (while package egress is allowed) so blanket offline mode cannot masquerade as CP isolation; (5) deliberate containment/canary probe traffic and planted canary values used by the harness must be **excluded** from unexpected-canary findings (tag probe sessions; canary scanner ignore-list for harness-owned probe IDs). | Distinguishes real policy denial from DNS/offline/tooling failure |

Gate outcomes for successful CP access: **D66**. | “Plane 2 never calls Plane 1” must be enforceable, not aspirational |
| D42 | **Trust-zone boundary matrix is canonical.** [ARCHITECTURE.md](ARCHITECTURE.md) must maintain zones (Internet · Edge · Control plane · Sandbox · External services) and a **From → To \| Allowed? \| Enforced by** table.
